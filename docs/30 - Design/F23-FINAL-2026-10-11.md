## 2. Scope

### 2.1 The data
- **Setup family** = the taxonomy `Family` enum, five values: `opening_drive`, `continuation`, `range_break`, `reversion`, `time_window` (`taxonomy/trade_def.py:116-121`). A def lists one or more (`trade_def.py:745`, `min_length=1`).
- **Setups** = the validated defs from the vault's strategy notes, read by `load_vault_trade_defs(vault_root)` (`taxonomy/vault_loader.py:472`), folder `1 - Trading/4 - Strategies` (`vault_loader.py:91`). Each `LoadedTradeDef` carries `slug`, `name`, `note_path`, `definition.family` (`vault_loader.py:135-147`). A setup with two families appears in both decks. Drafts (`VaultTradeDefs.drafts`, `:175`) carry no def and no family; they are listed on the run's stdout, never in a deck.
- **Cards** = radar cards: `"user".aset_sizings` rows with `origin = 'radar'`; each carries `trade_def_slug` NOT NULL by constraint (`db_migrations/0007_radar_cards.sql:78`). Card → family by `trade_def_slug` → the loaded def's `family`.
- [F-03] **Latest** (Grok C3, verbatim): Latest = every radar card in the family, no cap. Order is `formed_at DESC NULLS LAST, id DESC`. `configs/cobalt/playbook.yaml` key `latest_per_family: null` (null = all). A numeric cap is not committed in F23: this packet has no per-family count (redacted `[user data]`), so `10` is unmeasured. The live-note run stores the per-family counts on the `job_run` result; a later card may set the key from that measurement. A null `formed_at` is shown, never dropped, and never sorts ahead of a timed card. The title week is a label, not a filter.
- A card whose slug has no loaded def (def deleted or drafted since) goes to an `unfiled` deck, counted; never dropped (L1).
- [F-10] **Unfiled** (Opus seat C10, verbatim): "`unfiled.pptx` lists every radar card whose slug is not among the loaded defs, newest first with the same order as C3, each row carrying its slug and the reason: `draft` when the slug is in `VaultTradeDefs.drafts`, else `no note`. Same-day rerun (Grok C11, verbatim): A same-day rerun replaces that day's folder only after the new decks are complete. Under `data/playbook`: if `<date>.tmp` exists, delete it first; write every deck only inside a fresh `<date>.tmp`; if `<date>` exists, rename it to `<date>.old`; rename `<date>.tmp` to `<date>`; delete `<date>.old`. A crash before the tmp→date rename leaves the previous `<date>` in place. Never delete `<date>` first. Never write into a leftover tmp. Whether a directory rename on this volume is atomic, and whether a viewer holding a file blocks the rename, are EXPERIMENTS (X1, X2), not defects. (Grok's X1, X2 = this FINAL's E1.)
