## 1 The file-less no-trade event

### The fact

- **One home today.** The event lives on the day's current trading-log import row: `drc_imports.event_state` / `event_updated_at` / `event_error` (`0016_drc.sql:35`–`:37`, with the CHECK at `:42`). The 0016 header says "Three tables, no fourth (v2 §3): the input event's state lives on the import row" (`0016_drc.sql:3`–`:5`, which is v2 `:76` `[F-35]`).
- **`mark_event` accepts only a trading-log row.** `mark_event(import_id, state, error)` (`store.py:423`–`:455`) reads `SELECT kind, event_state … FOR UPDATE` (`:437`) and refuses any row that is not a `trading_log` (`:440`–`:441`).
- **`event_for` reads only the trading log.** `event_for(day)` (`store.py:456`–`:516`) takes the event from the current trading-log import alone (`:505`–`:511`).
- **The file-less day already records its statement and its day.** "No trades today" with no file is `imports.no_trade` (`imports.py:538`–`:567`). It writes the `no_trade` statement (`:555`) and runs `rebuild(effect_day(day, None))` (`:560`–`:562`). That writes the `day` row with `inputs.no_trade_id` (`store.py:831`–`:832`) and the `seed` row (`store.py:844`–`:861`; `source = no_trade_carry` via `_no_trade_seed`, `store.py:668`–`:690`).
- **But it has no event row.** No row carries pending → running → done | failed, and the build is not called. The page says `NO_TRADE_WAITS` (`imports.py:87`, `:566`, and the GET line `:683`–`:684`).
- **The zero-execution trading-log day is not affected.** Its event is on its import row (`_event` `kind`, `imports.py:264`; report `:207`).
- **Every existing path refuses a file-less row** (report `:94`):
  - `record_import` refuses a result with no kind (`store.py:206`–`:209`).
  - `name` / `sha256` are NOT NULL (`0016_drc.sql:27`–`:28`).
  - The `kind` CHECK has no `no_trade` (`:26`).
  - Forging a `trading_log` kind makes the forged row the day's current log for `_repair` (`store.py:554`, `:557`).
- **`drc_stated_books` is append-only.** The `drc_stated_books_append_only` trigger (`0018_drc_stated_books.sql:49`–`:51`) refuses every UPDATE and DELETE.
- **`record_day` deletes and rewrites a day's `drc_rows`.** The DELETE is per day (`store.py:758`), both for the recorded day and for every day `_commit` re-pairs forward (`:735`–`:758`).
- **A second door exists.** The CLI `cobalt drc state-book --no-trade DAY` (`cli.py:5`, `:99`–`:100`) writes the same `no_trade` statement and fires nothing.

### THE READING — option (B): one `drc_events` table, both day types

**Home.** Every `DrcInputsPlaced` event lives on ONE row of `"user".drc_events`, one row per source row:
- **A file day:** the source is the day's current trading-log import (`source = 'import'`, `import_id`).
- **A file-less no-trade day:** the source is the day's current `drc_stated_books` row with `kind = 'no_trade'` (`source = 'stated_book'`, `stated_book_id`). That row is v3 `[F-05]`'s "INPUT … one `drc_stated_books` row, `kind = 'no_trade'`, `positions = []`" (`v3:99`), and v3 `:268` already names it "the only event … with a stored `no_trade` input".
- **The columns move.** `drc_imports.event_state` / `event_updated_at` / `event_error` and their CHECK (`0016:35`–`:37`, `:42`) are dropped in the same migration. They have never shipped: `0016` is absent from `cobalt_dev` and production (report `:179`).
- **Nothing else changes.** `drc_stated_books` stays append-only. `drc_rows` stays a computed record.

**Which event is the day's event.** `event_for(day)` picks it in this order:
1. The current trading-log import exists → the event row with that `import_id`. A zero-execution log stays a file day with `kind = no_trade`, as built (`imports.py:264`).
2. Else the day's current `no_trade` statement exists (`_no_trade_id`, `store.py:538`–`:544`) → the event row with that `stated_book_id`.
3. Else → no event, and every event field is `None`.

A file dropped after a file-less event: the import's own event fires through `place()`, and the stated-book row stays as history. A restated `no_trade` gets a new statement id and a new event row.

**The store (the ONE writer, L40).** Store changes:
- **NEW `DrcStore.fire_event(day, *, import_id=None, stated_book_id=None) -> int`.** It takes exactly one source.
  - An `import_id` must be a stored `trading_log` row of `day` (today's check at `store.py:440`).
  - A `stated_book_id` must be the CURRENT `no_trade` statement of `day`. Otherwise it is refused, naming why, and nothing is written.
  - It inserts the source's row as `pending`, or moves an existing row for that source back to `pending`: error and note_path cleared (today's re-fire rule, `store.py:412`–`:414`). It returns the event id.
  - This is the only way a row reaches `pending`.
- **`mark_event(event_id: int, state: str, error: Optional[str] = None, *, note_path: Optional[str] = None) -> None`.**
  - It keys by the event id and moves only by `EVENT_MOVES` (`store.py:415`–`:421`, unchanged).
  - `failed` needs its reason, `done` needs `note_path` (see §3, ESCALATE 11), and no other state carries either.
  - The row lock is `SELECT … FROM drc_events … FOR UPDATE`.
- **`event_for(day)` keeps every key it returns today** (`store.py:507`–`:516`), except that the event keys are read from `drc_events` by the three-step rule above. It adds:
  - `event_id`
  - `source`
  - `stated_book_id`
  - `stated_book_sha256` (the statement's `book_sha256`)
  - `note_path`
  - `seed`: the day's `seed` row inputs `{source, from_day, from_book_sha256, stated_book_id, no_trade_id}` or `None`. Read only; nothing is computed.
- `import_id` is `None` on a file-less day.

**The event object** (`imports.DrcInputsPlaced`, `imports.py:131`–`:144`). Fields and rules:
- `event_id: int`: new.
- `import_id: Optional[int]`: was `int`.
- `stated_book_id: Optional[int]`: new.
- `stated_book_sha256: Optional[str]`: new; the statement's `book_sha256`.
- `seed_from_day: Optional[date]` and `seed_from_book_sha256: Optional[str]`: new; from the day's `seed` row, `None` when the day has none (L57: the carried seed the build reads).
- Everything else as built: `date`, `stats_import_id`, `screenshot_import_ids`, `sha256s`, `partial`, `kind`, `orphaned`.
- **Model rule:**
  - Exactly one of `import_id` / `stated_book_id` is set.
  - `stated_book_id` set ⇒ `kind == "no_trade"`, `stats_import_id is None`, `screenshot_import_ids == []`, `partial == {}`, `sha256s == {}`, and `stated_book_sha256` is a hex-64 string.
  - A breach is a `ValidationError` (L1).
- `imports._event` (`:246`–`:266`) builds either shape from `event_for`, never from a second copy.

**The file-less build path (D2's, replacing `NO_TRADE_WAITS`).** A NEW `imports.no_trade_event(day, stated_book_id)` runs these steps:
1. `fire_event(day, stated_book_id=…)` → `pending`.
2. `rebuild(effect_day(day, None))`. This is the `[F-17]` seam (4) effect already built at `imports.py:560`–`:562`. A `PairingError` / `ValueError` → `failed` with `record — <text verbatim>`; the statement is kept.
3. `event_for` → the event.
4. `running`.
5. `_run_build(event)` (`imports.py:476`–`:484`, unchanged).
6. `done` with `note_path = str(note)`, or `failed` with the reason on ANY exception (`BUILD_NOT_BUILT` as is), never `done` on an exception.

`imports.no_trade` calls it where it returns `NO_TRADE_WAITS` today (`:566`, the `trading is None` case). Nothing else in `no_trade` changes: the refusals `:541`–`:559`, the zero-execution-log branch's "no-trade day recorded", and `stated; <D> has no import yet` (`:567`), where no rebuild runs and so no event fires. `imports._fire` (`:412`–`:473`) is re-pointed from `mark_event(import_id, …)` to `fire_event(day, import_id=…)` + `mark_event(event_id, …)`, with its order unchanged.

**One path for the second door (L3).** The CLI `cobalt drc state-book --no-trade DAY --apply` (`cli.py:99`–`:100`) calls the SAME `imports.no_trade_event(day, <the written statement's id>)` after `record_stated_book` returns, and the CLI's own rebuild for that kind is replaced by it (the function runs the rebuild). No second event path. `via` stays the caller's (`cli`). The voice widget (K4, `via = voice_widget`) follows the same rule when it ships.

**The page lines.** The `NO_TRADE_WAITS` constant and its three uses (`imports.py:87`, `:566`, `:683`–`:684`) are removed.
- **On the action:** `no-trade day recorded → DRC built: <note path>` (the text built at `:470`), or `DRC build FAILED: <step> — <reason>` (`:422`).
- **On `GET /drc`:** the day's state for a file-less day is `no-trade`. `_state` (`imports.py:218`–`:225`) returns `NO_TRADE` when there is no current trading log AND the day has a current `no_trade` statement; it returns `WAITING_TRADING` only when there is neither. The status branches `:685`–`:694` then apply to both day types, and `done` reads `<prefix> → DRC built: <event_for's note_path>` (replacing the `(the note path is returned on the drop; not stored — D3)` text at `:687`).

**D3's contract (what `09` reads).**
- **D3 receives** `run_drc_build(event: DrcInputsPlaced)` for BOTH day types, only after the day's `day` row is committed.
- **A file-less day's event:**
  - `kind = "no_trade"`
  - `import_id = None`
  - `stated_book_id` / `stated_book_sha256` set
  - `stats_import_id = None`, no screenshots
  - `seed_from_day` / `seed_from_book_sha256` from the `seed` row (`None` when the day has no seed)
- **The build reads** `DrcStore().event_for(day)` and the day's `drc_rows` as stored, and never reads `drc_events` directly.
- **D3 writes no event state.** It returns the note path, and D2 stores it on `done`.
- **D3-2's first check** is "the event is `trades` … or `no_trade` (D2's event: on the current trading-log import, OR on the current `no_trade` statement) AND the day's `day` row exists". A file-less event whose `day` row's `inputs.no_trade_id` ≠ `event.stated_book_id` FAILs and writes nothing (L57: the event and the rows name the same input).

## 2 The screenshot writer

### The fact

- **The schema is ready.** `0016` has the `screenshot` kind and `trade_key`, and requires a `trade_key` for a screenshot row (`0016_drc.sql:26`, `:29`, `:39`).
- **The code has no writer.** `models.Kind` has only `TRADING_LOG` / `STATS_LOG` (`models.py:43`–`:47`). `record_import`'s INSERT names no `trade_key` (`store.py:226`–`:231`), and its supersede predicate is kind + date only (`:216`–`:225`).
- **So every real image is refused.** The per-trade drop zone (`web.py:1567`–`:1577` → `imports.place(…, trade_key)` → `_screenshots`, `imports.py:309`–`:310`, `:361`–`:374`) refuses every real image with `SCREENSHOT_NOT_BUILT` (`:89`–`:92`).

- **Screenshots are optional.** R91 makes them optional: both-placed does not depend on them (`_state`, `imports.py:218`–`:225`, reads no screenshot).
- **B13 is AUTO.** v2 `:321` (B13) is "embed of the dropped screenshot", and v2 `:89` `[F-14]` says the drop zone binds the image and nothing is read from it.
