## Decision (default)
**A, staged on C. Never B in Phase 1.**

1. [F-01] F21 ships in two chunks. Chunk 1 (the floor): a new-core memory module with one table carrying a `tsvector` column, an importer and a search command; it meets the acceptance test with no model call. Chunk 2: a `local.embed` route on the existing loopback lane through `cobalt.modelaccess`, declared as its own route KIND (an embeddings kind with its own Route variant, adapter method and result type), never as an `openai_compatible` chat route; no `fallback` key; never a cloud embedder in Phase 1.
   *(the Anthropic seat, D1, verbatim)*

2. [F-02] The F21 table is a new-core table on the `"user"` side (L32: the ledger and his vault history are user data), declared in `src/cobalt/db_migrations/placement.py` before it exists, with `user_id NOT NULL` and its FK, created by the module's own migration. The vector column arrives in chunk 2's migration with its dimension written in the DDL; the config key holding the dimension is checked against the column's declared dimension at load and a mismatch crashes (L1, L10). Every row records the embedding model as returned by the server and the dimension. A model swap that keeps the dimension is a re-embed job; a swap that changes it is a migration of this one table. The four 1536-dim tables are untouched.
   *(the Anthropic seat, D2, verbatim; the wrong-length behaviour it rests on is X10)*

3. [F-03] This ADR names no embedding model. The F21 card's preflight calls `/v1/embeddings` on the loopback lane. If that call does not return a vector, the card records `vectors: DEGRADED` and F21 ships FTS-only; vectors are a follow-up card. The preflight never writes a zero vector and never exits 0 while claiming vectors exist. Cloud is never the substitute.
   *(Grok, D3, verbatim)*

4. Cloud (B) can come back only by a routing-tribunal ruling that adds a non-local lane (`config.py:73-74`; L25's "by ruling, not by fallback", LAWS:188). *(ADR kept — D4, ADOPT by both seats)*

5. The old `OPENAI_API_KEY` embedding path (`postgres.py:745-764`) is not ported. *(ADR kept — D5, ADOPT by both seats)*

6. [F-14] An embed HTTP error, a model that is not loaded, a timeout, or a vector whose length is not `embed_dim` raises and writes no vector. The row keeps its FTS body only. The card records `vectors: DEGRADED` when no model answers. New code never returns a zero vector and never returns `None` and continues (`postgres.py:259`, `:264` are the forbidden exits).
   *(Grok, (c), verbatim)*

7. [F-15] Named seams: the route lives in `configs/cobalt/modelaccess.yaml` (the one registry); the table is `"user".<name the card fixes>` declared in `placement.py`; the search function and its CLI are F21-owned and are the only recall entry for F20, the dream job (R4, Charter:398) and the observation store (O3); the one-shot embed command is owned by F21's builder until a dream job design takes it over by its own card. The voice path is a neighbour, not a consumer: it shares the registry file and the server, so chunk 2 lands with the restart of (f) and the contention rule of T4.
   *(the Anthropic seat, (d), verbatim — the table name is ROUND 2 item R2-1)*

Why: B is blocked by frozen law and by the schema in code. C alone meets the acceptance test but leaves H1/H6 (recall by meaning, the "dream" job) without a base. A costs nothing per call, follows L23, and the staging means F21 never blocks on it.

## Cost and storage (what can be proven)
- [F-13] Corpus: `PROJECT-LEDGER.md` was 515,281 bytes and 3,765 lines at drafting (`wc -c`, `grep -c`); it is a live file, 528,184 B at the round-1 read (the hub's FC17 HOLDS). The memory folder is 984 KB on disk (`du -sk`). That is about 1.5 MB of text. The rest of "vault history" has no size proven here (UNKNOWN).
- Vector storage: pgvector stores `vector(n)` as 4·n + 8 bytes (pgvector's published layout, not proven in this repo). That is 6,152 B a row at 1536 dims and 3,080 B at 768. At an ASSUMED 2,000 bytes per chunk, ~1.5 MB is ~750 chunks, so ~4.6 MB of vectors at 1536 dims or ~2.3 MB at 768. **Storage does not decide this.** (Arithmetic checked by the hub, C14: ARITHMETIC OK.)
- Cloud spend: the token count is ~1.5 MB ÷ ~4 bytes/token ≈ 375k tokens (a heuristic, not measured). The repo carries no price for `text-embedding-3-small`, so cost is UNKNOWN. A for that corpus is $0 marginal (L24 rung 1).
- Local throughput and latency of an embedding model on the host: UNKNOWN (no measurement exists, and the X-E4 numbers at `modelaccess.yaml:31-35` are chat Plan calls). X2 / X8 measure them.
