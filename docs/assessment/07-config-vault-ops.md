## 2. VaultManager — what exists vs what a rekey/rotation feature needs (H-3)
Exists: generate key, unlock (decrypt to RAM), lock, get/set/delete/list, save (full rewrite). Missing: atomic write, backup/versioning, rotation (`Fernet.rotate` or decrypt/re-encrypt), key-from-`getpass`, integrity check on load beyond Fernet's HMAC, path validation (absent file ≠ empty vault), single shared instance (today ≥7 `VaultManager()` instantiations + per-`add_log` unlock, Pass 1), audit log of secret access (names only), rate/plausibility checks. Docstring fix: Fernet ≠ AES-256.

## 3. Dual start / supervision (H-4) — recommendation shape (not applied)
Make launchd the supervisor: plist runs `uv run src/cobalt_agent/main.py` **directly** (no `nohup`, no PID file) with `KeepAlive` + `ThrottleInterval`, `WorkingDirectory`, env from a launchd-safe source (not a sourced shell file), stdout/err to rotating files; `cobalt.sh` becomes a thin `launchctl kickstart/stop/print` wrapper; pre-flight waits move into the app (retry loop) or a `KeepAlive.OtherJobEnabled` dependency on `com.cobalt.mainframe`. Verify `uv run` signal forwarding or exec Python directly.

## 4. Logging policy (H-5) — minimum set
Single `cobalt_agent.logging.setup(entry, level)`; remove loguru default sink in every entry (incl. dev_utils, pytest via conftest); structured file sink with rotation/retention; redaction filter for vault values/tokens/`auth=`; forbid payload dumps (config, WS frames, tool args) above DEBUG; DEBUG only in dev profile; delete `config.py:622`, `mattermost.py:77`; stop double-capturing via `cobalt.sh` redirection.

## 5. docker-compose (H-6) — minimum set
Put `pgadmin` in the `core` profile (or drop profiles); pin images; bind ports to `127.0.0.1` (Tailscale access via host); separate Mattermost DB (or accept and document the coupling + backup both); healthchecks; move `data/postgres` out of the repo or keep and document; `env_file` contract with `.env.example` filled in.
