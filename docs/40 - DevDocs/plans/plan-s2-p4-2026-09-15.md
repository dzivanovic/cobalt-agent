## §0 Headline

- **Value column (R1):** `system.radar_membership` gains `rank_metric` + `rank_value`, written by S1 on every scan. `/radar` shows the value next to the metric name. No backfill: rows from before the deploy stay NULL and render `—`.
- **F3 picks (R2):** a pick is a card reaching FILLED. One `"user".picks` row is written inside the `CardStore.fill` transaction and snapshots pool rank, metric, value, `card_score` and card-score rank at pick time. The row exists now; DRC rendering lands in S3.
- **F12 + F13 (R3/R4/R5):** new one-shot `com.cobalt.replay` at 21:05 ET weekdays, after the reset and after the archiver.
  - It fetches unfiltered top movers, archives their i1 bars, and replays today's unfilled cards over i1 bars.
  - Each miss becomes a `"user".missed` row with `excluded_by` and one counterfactual R (hard stop → window end) plus all its inputs (L57).
  - It diffs the benchmark movers against the in-play set and upserts ONE miss line as unit `drc-misses/miss_line` into that day's DRC note.
- **S2 smoke (R6):** `cobalt smoke s2`, a read-only command in the day-open pattern: a numbered check table, PASS/FAIL/KNOWN/ERROR, and a report file. The checklist in STEP-9 is its spec. If the build slips past 09-22, the hub runs the checklist by hand.
- ESCALATE: 4 (§8). Engine trade_def formations are replayed only once P2's evaluator exists. Until then there is one loud line and no fake rows.

- **STEP-5 F12 replay + counterfactual R (R4)** — `replay/cards.py`, pure functions over `Bar` lists plus one store:
  - **Candidates:** `aset_sizings` created that ET day whose state history (`card_transitions`) never reached FILLED.
  - **Bars:** `system.bars` i1 for the ticker from `created_at` to 16:00 ET. Missing or stale bars (watermark < 15:59) → the row is not written, the reason is logged as `input_stale`, and the job counts it (loud, never a fake R).
  - **Trigger:** the first bar with `high ≥ entry` (long) / `low ≤ entry` (short) at or after `created_at`. `fill_price = entry`, or `open` if that bar opened beyond entry. No trigger → no row.
  - **`excluded_by`**, the first matching gate in fixed order:
    1. `rule_10`: ≥2 cards FILLED and not CLOSED at `trigger_ts`.
    2. `window`: `trigger_ts` > `_resolve_window_end`.
    3. State at `trigger_ts` from `card_transitions`: WATCH → `unarmed`, PASSED → `passed`, ARMED/TRIGGERED → `not_filled`.
    - `gate_detail` records every gate's evaluation. `trade_count_band` is recorded as `unset` while the tunables are null (§8 item 2) and is never an `excluded_by` value.
  - **Horizon end** = window end if `trigger_ts ≤` window end, else 16:00 ET (decided with veto).
  - **Exit:** walk bars from the trigger bar. The stop is touched if `low ≤ stop` (long) / `high ≥ stop` (short); on the trigger bar itself a stop touch counts (tie → stop). First touch → `exit_price = stop`, `exit_reason='stop'`. Otherwise the close of the last bar ≤ horizon end.
  - `cf_r = (exit_price − fill_price)/|entry − stop| × (+1 long / −1 short)`, rounded half-up to 4 dp once. `mfe_r` = best excursion before exit in the same units.
  - `inputs_sha256` = canonical JSON of {entry, stop, direction, created_at, window_end, horizon_end, bar ts range, bars_watermark, formula_version}.

Each formation whose trigger fired with no open radar card for (member, def, direction) → `kind='formation'`, `excluded_by='no_card'` (or the card's state per the gates), same R formula.
