## §2 Decisions

### D1 — Sources: two vault notes, four block kinds, one parser

- **Screens note** `1 - Trading/Radar Screens.md` (exists):
  - *screen block* — a fence with no `kind` key. `ScreenBlock` (extra=forbid): `screen` (display name → key = snake slug, unique), `f` (`^[a-z0-9_.]+(,[a-z0-9_.]+)*$`; `%`, `&`, `=`, `auth` refused), `sort` (`^-?[a-z0-9_]+$`), `columns` (list[int] 0–150, display only), `active_from` / `active_to` (`"HH:MM"` ET, from < to), `enabled` (bool), and OPTIONAL `ft` (int 0–99, absent by default; sent as `&ft=` only when present). `ft` exists from the first deploy, so the E4 outcome never needs a schema change.
  - *pool block* — `kind: pool`, its own schema (D2). Exactly one per note.
- **Lists note** `1 - Trading/Radar Lists.md` (new, R4):
  - *list block* — no `kind`. `ListBlock` (extra=forbid): `list` (key), `description`, `tickers` (uppercase, unique), `radar` (bool: pool source), `archive` (list[`Interval`]), `backfill_default` (exactly one true across blocks), `enabled`. E3: the three tiers move as they are; membership `source` = `list:tier_a@<sha12>`.
  - *exclude block* — `kind: exclude`, `tickers`; at most one → `excluded_by = manual`.
- **Dispatch:** no `kind` → the note's default block, validated strictly; `kind: pool` (Screens) or `kind: exclude` (Lists) → that schema; any other `kind` value, or a kind in the wrong note → a named parse failure. A fence is never skipped.
- **Parser** `cobalt.radar.notes`: reads the file bytes once per check and hashes those bytes (no torn reads under Obsidian Sync); only ```` ```yaml ```` fences; prose and `cobalt:` markers ignored; sha256 per block and per note.
- **Why vault notes:** R1 already makes a note the truth for screens; one parser, hash, mirror and degradation path serve screens, pool rule and lists. A separate Lists note keeps ~260 tickers out of his screen prose and gives the lists write its own write_id.
- **Mirror:** `TraderSettingsStore.put` (the one write path, `settings/store.py:60`). Keys `radar.note.screens`, `radar.note.lists`, `radar.screen.<key>`, `radar.pool`, `radar.list.<key>`, `radar.exclude`; value `{block, block_sha256, note_sha256, status: ok|parse_failed|missing|removed, error}`; `source = vault:<note path>@<sha12>`. "Changed" is decided against the STORED `note_sha256`, so a skipped mirror stage is redone next cycle (D5).
- **Failure:** a failed screen or list block contributes nothing; its mirror row → `parse_failed`; its members are HELD (D3 step 3); pool row degraded naming it; F18 RED. A pool block that is missing, duplicated, invalid or over budget (D2) → the pool is FROZEN (D3 step 0), mirror `radar.pool` → `missing` or `parse_failed`, pool row degraded with source `pool_block`, F18 RED. Never an empty pool from a failure; the DB never presents a previous version as current.
- **R2 fixtures** (the repo's only screen definition, synthetic): `tests/fixtures/radar/radar-screens.example.md` — ONE screen block `example_session_scan` (`active_from: "10:00"`), ONE pool block (`cap: 5`, `stickiness_scans: 2`, `rank_metric` for all three sessions, `overrides: {example_session_scan: {first_from: "10:00"}}`), and prose in the "Export call (derived)" shape the proposer reads (D13); `tests/fixtures/radar/radar-lists.example.md` — ≥60 large caps by rule, one ETF (`not_equity`), one exclude block. Test variants are `model_copy` of fixture objects, never a second definition.
- **R2/E5 suite test** (content, not filenames): no tracked file under `src/cobalt/`, `configs/cobalt/`, `tests/cobalt/`, `ops/` or `docs/40 - DevDocs/` contains `f=` followed by `sh_|ta_|fa_|an_|cap_|exch_|geo_|idx_|ind_|sec_|news_|earningsdate_|ipodate_|targetprice_`, outside `tests/fixtures/radar/`. ### D2 — The pool block (`kind: pool`): the trader's rule

The 09-10 ruling, as the proposal renders it (D13). No committed config file carries these values.

```yaml
kind: pool
cap: 50                     # hard; never exceeded
priority: [screens, lists]  # a permutation of both
rank_metric:                # exactly these three keys
  premarket: volume         # 04:00–09:30 (F1 session clock)
  rth: rvol                 # 09:30–16:00
  aftermarket: volume       # 16:00–20:00 — architect decision, veto-able (E10)
overrides:                  # keyed by screen key; each must name a screen block in this note
  morning_low_float:
    rank_metric: volume     # this screen ranks by volume in every session
  day_scan:
    first_from: "10:00"     # first among screens from this time; at most one screen
stickiness_scans: 3         # integer ≥ 0
```

- Pydantic extra=forbid at every level; `rank_metric ∈ {volume, rvol}`; `cap ≥ 1`. An override key that names no screen block → the pool block is `parse_failed`, naming the key.
- **Scanned sessions** = the `rank_metric` keys. The schema admits no `overnight` or `market_reset` key, so those sessions never scan.
- **Budget**, checked on every pool-block load: `cap × 60 / radar.poll_interval + (active screens + list chunks) × 60 / radar.scan_interval ≤ radar.finviz_max_rpm`. Over budget → the pool block is invalid (D1 failure), with the computed numbers in the reason.
- Metric values come from export columns named in `radar.yaml` `export.metric_headers {volume, rvol}` (engine config, pinned from a real header capture).

### D3 — Ranking and stickiness: the pure function `cobalt.radar.pool.decide`

A scan ranks ALL candidates. Nothing carries over between scans except each open episode's `below_cap_streak` and `last_rank`.

**Rank key** (lexicographic total order; a volume number is never compared with an RVOL number):
1. group, in `priority` order (a name listed by any healthy active screen is in `screens`);
2. screens group only: 0 if the name is on the `first_from` screen and `now_et ≥ first_from`, else 1;
3. position: the name's 1-based rank inside its best screen's export, sorted by that screen's metric (override, else the session's) descending; list-only names rank inside the union of radar lists by the session metric; a blank metric cell sorts after every valued cell;
4. note order of that screen;
5. ticker ascending.

**Decision**, in precedence order:

| Step | Condition | Result |
|---|---|---|
| 0 | pool block not ok (D1) | FREEZE: no membership transition; pool row degraded `pool_block` |
| 1 | open member is in the exclude block | leaves, `manual` |
| 2 | every source that listed the open member is inactive (window or `enabled: false`) and no active source lists it | leaves, `screen_inactive` |
| 3 | open member not listed by any healthy source but listed by a degraded one | HELD: keeps its seat, streak frozen |
| 4 | candidate is excluded / fails `not_equity` | never admitted, `manual` / `not_equity` |
| 5 | seats = cap − held; if held > cap (cap lowered), the held with the worst `last_rank` leave until held = cap | leaves, `config_cap` |
| 6 | W = the top `seats` of the ranked, non-held candidates — the PROVISIONAL winners, fixed for the rest of the scan | W |
| 7 | open member ∈ W (a genuine rank recovery) | `below_cap_streak = 0`, `last_rank` updated |
| 8 | open member ∉ W (ranked below W, or listed nowhere): `below_cap_streak += 1`; if the streak now exceeds `stickiness_scans` | leaves, `config_cap` if still ranked, `excluded_by` NULL if listed nowhere |
| 9 | final pool P starts as W; the remaining step-8 members, best current rank first (unlisted after ranked, then `last_rank`, ticker), each replace the lowest-ranked newcomer still in P; when P holds no newcomer | retained with its streak KEPT (retention never resets it) / leaves as in step 8 — the cap is hard |
| 10 | newcomer ∈ P | admitted, `entered_at`, `rank_at_entry` |
| 10 | ranked candidate ∉ P and not an open member (incl. a newcomer displaced in step 9) | never-admitted episode, `config_cap` |

- **Invariant** (property-tested): admitted open members = held + |P| ≤ cap, and |P| = |W|, after every scan, for every input, including cap reductions and degraded sources.
- **Streak:** counts consecutive SCANS (idle and paused cycles do not count); reset to 0 only by step 7; kept by step 9; frozen while held. A member outside W therefore leaves on the (`stickiness_scans` + 1)-th consecutive scan, whether or not it was retained. Case (property test): cap 1, `stickiness_scans: 3`, incumbent A always ranked below newcomer B → A retained at streaks 1, 2, 3; A leaves at 4 and B is admitted on that scan.
- **Reading of the ruling:** "fell below the cap" includes a member that dropped off every active source (screen-filter flicker between scans) — veto-able (E11).
- **Morning Low Float** ranks by volume in every session (its override); **Day Scan** ranks first among screens from 10:00 (its `first_from`); its own `active_from: "10:00"` window also gates it.
- **Episodes:** admitted → `entered_at`, `excluded_by` NULL. Never admitted → `entered_at` NULL + `excluded_by`, closed when it stops being a candidate. A later admission closes that episode and opens an admitted one (J1 points at admitted episodes). The first scanning cycle of a new ET trade date closes every open episode at the prior aftermarket close (`excluded_by` NULL): stickiness never carries across days.

- **Rollback domain (F2):** `cobalt db migrate --rollback` REQUIRES `--down-to NNNN` and runs only the reverse files of registered migrations newer than NNNN, newest first; without it, it refuses before connecting and lists targets. Hardening verdict: adopted.
- Round trip (hub, H1): `migrate → --rollback --down-to 0003 → migrate` → identical digests; 0003's columns survive; radar tables CREATED → DROPPED → CREATED; the seed row present → absent → present.

### D5 — Resident `com.cobalt.radar`: loop, sessions, stage order (D6 ruling)

- **Registry:** resident, `supervisor: self`, `timeout_s: 300`, `enabled: false` at merge (flipped at L11 — `com.cobalt.herdr` precedent, `jobs.yaml:127-136`), `reads:` derived by instrumenting one cycle's `open`/`read_text` (09-09 method), `imports: [cobalt.cli]` (§3).
- **Plist:** `/Users/cobalt/.local/bin/uv run cobalt radar run`; `WorkingDirectory /Users/cobalt/cobalt`; `RunAtLoad true`; `KeepAlive {SuccessfulExit: false}` (a kill-switch exit 0 is not respawned; a crash is); `COBALT_ENV=production`, `COBALT_VAULT_PATH=/Users/cobalt/Vault/Think`; `logs/radar.{log,err}`. `ops/README.md`: after `cobalt resume`, `launchctl kickstart gui/$(id -u)/com.cobalt.radar`.
- **Loop:** `job_run("com.cobalt.radar")`; `should_keep_running` each cycle; one cycle per `radar.scan_interval`. `scan_id` = cycle start as UTC epoch milliseconds, strictly greater than the stored `last_scan_id` (otherwise the cycle is refused, loud).
- **Session asked first** via `session_clock().session(now)`, never inferred from a caught `SessionBlocked` (F10). A session with no `rank_metric` key → `idle`, no Finviz call. `market_reset` → `paused_market_reset`, zero radar writes; only the wrapper's F17 heartbeat stamps.
- **Stages.** A cycle = reload notes → fetch → `decide` (pure) → **S1 membership → S2 pool row → S3 mirror → S4 bars**. Each stage is its own transaction on its own side's connection: S1 `RadarStore` (system); S2 `RadarStore` (system); S3 `TraderSettingsStore.put` (user; only when a stored `note_sha256` differs); S4 `BarStore.upsert_bars`, one transaction per ticker (system). There is no cross-store transaction (F11).
- **Idempotency:** S1 on `(scan_id, ticker)` — episode opens `ON CONFLICT DO NOTHING` on `(pool_key, opened_scan_id, ticker)`; updates and closes apply only `WHERE last_scan_id < scan_id`. S2 on `scan_id`. S3 on `(key, note_sha256)`. S4 on the bars primary key.
- **Commit seam:** every store write the radar uses takes `before_commit: Optional[Callable[[], None]] = None`, called after its statements and immediately before its commit, inside the store's own transaction: `RadarStore` (S1, S2); `TraderSettingsStore.put(rows, *, source, before_commit=None)` — just before `conn.commit()` (`settings/store.py:90`); `BarStore.upsert_bars(bars, *, before_commit=None)` — the last call inside `with self._connect() as conn:` (`archiver/store.py:73`), so a raise rolls back through the context manager. Default `None` keeps today's behaviour for every existing caller (archiver, settings CLI).
- **market_reset crossing:** the runner passes `before_commit = gate(stage)`, which asks `session_clock().session(now)` and raises `StageDropped` (radar's own exception) in `market_reset`. The raise rolls that transaction back; that stage and every later stage of the cycle, every remaining S4 ticker included, are skipped and logged `dropped at <stage>[:<ticker>]`; nothing commits inside the window. S4 tickers committed before the boundary stay (idempotent). The next non-paused cycle stamps the dropped stage as `failed_stage`.
- **Partial failure:** S1 fails → S2 still runs, writing `degraded = true`, `failed_stage = membership`, then the cycle stops. S2 fails → loud log, stop (F18 turns RED on `last_scan_at` age). S3 fails → the pool row is re-stamped `failed_stage = mirror`; S4 proceeds. An S4 ticker fails → a `poll_failures` entry on the pool row. The next cycle recomputes from stored membership and stored mirror hashes, so a skipped stage heals itself.
- **Belt:** `RadarStore` writes call `assert_writable("radar.<stage>")`. If it raises despite the check, that is a logged stage failure as above, never a retry loop.

### D6 — Fetch: one Finviz transport (D8 ruling)

- `archiver/collector.py` gains `finviz_get(path, params, token, *, on_metrics=None) -> httpx.Response`, the one HTTP call for every Finviz export. Client settings unchanged (timeout 30 s, `follow_redirects=True`), so the archiver behaves exactly as today. `on_metrics(FetchMetrics)` fires for every attempt, before `raise_for_status`: `status`, `redirect_statuses` (from `response.history`), `elapsed_ms`, `bytes`, `content_type`, or `error` (exception class) on a transport failure.
