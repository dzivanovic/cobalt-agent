# `src/cobalt/settings/fills.py`

## What it does
The ONE reader of his fill-drift setting (S3 exits v3 §4; his ruling O2 = A, `cto-2026-09-28.md` R35): `drift_warning_pct(source) -> Optional[Decimal]` reads `"user".trader_settings` key `fills.drift_warning_pct`. `source` is an open connection (THE fill reads it inside its own transaction, `SELECT value FROM trader_settings WHERE key = %s`) or anything with `values()` — `TraderSettingsStore`, or a constructed store in tests (L69). The fill warns when `distance_change_pct > P` (`aset.engine.compute_fill_recompute`). No committed default (L53): a missing key returns None, the fill is still recorded with `drift_warning_pct` / `drift_warned` NULL, and `/fill` shows `DRIFT_NOT_EVALUATED` = `RE-READ STOP — setting fills.drift_warning_pct missing, warning not evaluated` (L1: loud, never a refusal). A present value that is not a JSON number `> 0` (a string, a bool, null, 0, a negative) raises `TraderSettingsError` naming the key. Not loadable yet: `cobalt settings load` accepts only the keys `settings/models.py` declares, which is the DRC lane's file (C1 report, X-S).
