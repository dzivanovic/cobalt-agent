# `src/cobalt/radar/handicap.py`

The float / market-cap handicap's pure functions (FLOAT-HANDICAP-v3, H1). Nothing in this module sorts the pool and nothing in it holds a value of the trader's: the thresholds, the factor, the combinator and the missing rule are read from his `HandicapBlock` each call.

## The group verdict (STEP-3, v3 §3 [F-10])

`handicap_group(metrics_row, block)` is the one place a name's group membership is decided, shaped like `config.is_not_equity`. It reads the `float_m` and `market_cap_m` the radar's `_collect` put into the name's `SourceSet.metrics` row (parsed by `runner._number` from `export.handicap_headers`), converts them to `Decimal` through their text so the stored digits are the export's, and compares them with the block's thresholds by strict `<`. Under `combinator: any` a name is `yes` when one known value meets its threshold, `no` when both are known and neither does, and `unknown` when a blank could still change the answer; under `all` it is `yes` only when both are known and both meet, and `unknown` whenever either is blank. Blank, `-` and unparseable are always `unknown`, never a silent `no` (L1). The verdict carries both cells and a plain-words reason (`float`, `cap`, `float and cap`, `neither`, `blank …`) — never a threshold.

## The shadow would-be rank (STEP-4, R26 B)

`shadow_rank(ordered, ranks, source_for, sources, block, headers)` is the step `pool.decide()` calls once per scan. For every ranked name it takes the verdict from the source that ranked it (`source_for`), gives it the block's `factor` when the verdict applies it (`yes`, or `unknown` under `missing: apply`) and 1 otherwise, divides the raw rank by that factor in `Decimal` (a float key can break an exact tie that `Decimal` keeps), and re-sorts pool-wide by `(quotient, handicapped, raw rank)` so an exact tie goes to the unhandicapped name. The result is one `HandicapRecord` per name — v3 §6's ten keys, `position` = raw rank, `effective_position` = the would-be rank, the source, the block's `missing` / `mode` as read and its sha256 — plus the factor, which the membership row stores. Nothing it returns reorders the pool. A `mode: live` block yields the degraded reason `mode live needs H2 — ranking raw`.

## The dead column (STEP-4A, his R54 "B")

`dead_columns(sources, ranked, headers)` runs inside `shadow_rank` before any factor is assigned. A healthy, active source's float or market-cap column is DEAD on a scan when its header is missing from the export (the collector then stores `None` for every name) or when every equity row of that source that reaches ranking has the cell blank, `-` or unparseable; one parseable cell makes it live. Any dead column makes the handicap INOPERATIVE for the whole scan: every ranked name gets factor 1 — a computed, stored outcome, not the NULL of a failure — its would-be rank equals its raw rank, and every record's reason, like the scan's degraded `handicap` reason, reads `handicap inoperative — dead column: <header> (<source>)`. It overrides `missing` for that case only; a single blank cell on a live column still follows `missing` (R52). A source with no equity row reaching ranking has no column to judge and is neither dead nor live — the reading this build took for a case R54's words leave open (one of his lists carries only funds); it is escalated for the desk.
