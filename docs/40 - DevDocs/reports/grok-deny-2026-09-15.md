## 1. Deny primitive — found

Source, read in full: `~/.grok/docs/user-guide/18-sandbox.md` (local
install docs, 303 lines).

Verbatim (lines 62-80, 92-101, 112-121):
> "Create custom sandbox profiles in `~/.grok/sandbox.toml` (global) or
> `.grok/sandbox.toml` (per-project): ... `deny = ["/data/shared-secrets",
> "**/.env", "**/*.pem"]` ... Paths or globs to kernel-deny (read +
> write/rename; see notes below). ... A non-empty `deny` list is
> **kernel-enforced**. Denied paths are **read-denied and
> write/rename-denied** via Seatbelt on macOS and a bwrap bind-over on
> Linux, so a denied path can neither be read (via `bash`, `grep`, or
> subagents) nor relocated out of the deny set and read elsewhere."

`extends` accepts a built-in base (`workspace`, `devbox`, `read-only`,
`strict`); a custom profile inherits that base's read/write shape and adds
`deny` on top (line 96).

Corroborating sources:

  `[profiles.readonly-safe]` — matches `docs/40 - DevDocs/reports/
  grok-launcher-diag-2026-09-14.md`'s citation of it. No custom
  `[profiles.workspace]` exists; `workspace` is the **built-in** profile
  (18-sandbox.md line 40) — the item-5 instruction's "keep the existing
  readonly-safe and workspace profiles verbatim" only has `readonly-safe`
  to preserve on disk; `workspace` is preserved automatically because
  `cobalt-job` reaches it via `extends`, not a copy.
- `~/.grok/sandbox.toml.pre-p4` (read): 0 bytes — confirms no prior custom
  `workspace` entry was ever backed up either.
- `grok --help` (run): `Commands:` list has no `sandbox` subcommand
  (`grok sandbox --help` does not exist); the primitive lives entirely in
  `--sandbox <PROFILE>` / `GROK_SANDBOX` + `sandbox.toml`, not a CLI verb.
- `strings "$(readlink -f "$(which grok)")" | grep -iE

- Web, `github.com/xai-org/grok-build` →
  `crates/codegen/xai-grok-pager/docs/user-guide/18-sandbox.md`: same
  text as the local file verbatim — local docs are current upstream, not

- Web (same source): "to deny a literal file whose name contains
  [glob metacharacters], name a parent directory instead" — this

  read-denied recursively, not just as an exact-path node. This is an
  **inference from the doc's own stated workaround**, not a sentence that

## 2. Profile written — `ops/grok-sandbox.toml`

```toml
[profiles.readonly-safe]
extends = "read-only"
restrict_network = false

[profiles.cobalt-job]
extends = "workspace"
deny = [
  "/Users/cobalt/cobalt/.env",
  "/Users/cobalt/.cobalt/",
```
