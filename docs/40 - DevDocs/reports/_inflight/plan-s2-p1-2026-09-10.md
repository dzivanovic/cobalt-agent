## §2 Decisions

### D1 — Sources: two vault notes, one parser (R1, R4)

- **Screens** — `1 - Trading/Radar Screens.md` (exists). `ScreenBlock` (extra=forbid): `screen` (display name → key = snake slug, unique), `f` (grammar `^[a-z0-9_.]+(,[a-z0-9_.]+)*$`; `%`, `&`, `=`, `auth` refused), `sort` (`^-?[a-z0-9_]+$`), `columns` (list[int] 0–150, display only), `active_from` / `active_to` (`"HH:MM"` ET, from < to), `enabled` (bool).
- **Lists (R4 choice)** — NEW note `1 - Trading/Radar Lists.md`. `ListBlock` (extra=forbid): `list` (key), `description`, `tickers` (uppercase, unique), `radar` (bool: pool source), `archive` (list[`Interval`], may be empty), `backfill_default` (exactly one true across blocks), `enabled`. One optional `ExcludeBlock` `{exclude: [tickers]}` → `excluded_by = manual`.
- **Why a vault note, one path:** R1 already makes a note the truth for half the radar's inputs; the same parser, hashing, mirror and degradation code serve the other half with no new machinery. A `trader_settings`-only path would need a second editing surface (seed YAML + CLI) and split radar inputs across two homes. **Why a separate note:** ~260 tickers would bury his screen prose, and `create_if_absent` gives the lists write its own write_id without touching `Radar Screens.md`.
- **Parser** (`cobalt.radar.notes`): reads the file bytes ONCE per check and hashes those bytes (no torn reads under Obsidian Sync). Only fenced ```` ```yaml ```` blocks are read; every yaml fence in a note must validate as that note's block type (a non-validating fence = a named parse failure, never skipped). Prose and `cobalt:` markers are ignored. Hashes: sha256 per block (fence body) + sha256 per note.
- **Reload:** note sha256 compared each cycle; on change → re-parse → mirror.
- **Mirror:** `"user".trader_settings` through the existing `TraderSettingsStore.put` (the one write path, `settings/store.py:60`). Keys `radar.note.screens`, `radar.note.lists`, `radar.screen.<key>`, `radar.list.<key>`, `radar.exclude`; value `{block, block_sha256, note_sha256, status: ok|parse_failed|removed, error}`; `source = vault:<note path>@<sha12>`. No new user-side table.
- **Parse failure (R1):** the failed block contributes nothing; its mirror row → `parse_failed` (the DB never presents the previous version as current); pool row `degraded = true` naming the source; members whose every source is degraded are HELD; F18 `radar` RED naming the screen/list. Never an empty pool from a failure.
- **R2 fixtures:** `tests/fixtures/radar/radar-screens.example.md` — exactly ONE synthetic screen, fenced format, `active_from: "10:00"` (exercises the gate); `tests/fixtures/radar/radar-lists.example.md` — synthetic lists (≥60 liquid large caps by rule, one ETF for `not_equity`, one `exclude`). The seed-parser test renders its prose input FROM the screen fixture, so no second screen definition exists. Suite test (content, not filenames): no tracked file under `src/cobalt/`, `configs/cobalt/`, `tests/cobalt/`, `ops/` or `docs/40 - DevDocs/` contains Finviz filter grammar (`f=` followed by `sh_|ta_|fa_|an_|cap_|exch_|geo_|idx_|ind_|sec_|news_|earningsdate_|ipodate_|targetprice_`) outside `tests/fixtures/radar/`. It also catches E5 if that report is committed unredacted.

### D3 — Tables: `db_migrations/0004_radar_pool.sql` (+ rollback)

```
system.radar_pool
  pool_key         TEXT PRIMARY KEY CHECK (pool_key ~ '^[a-z0-9_]+$')
  state            TEXT NOT NULL CHECK (state IN ('scanning','idle','paused_market_reset','stopped'))
  degraded         BOOLEAN NOT NULL DEFAULT false
  degraded_sources JSONB NOT NULL DEFAULT '[]'   -- [{source, reason, since}]
  sources          JSONB NOT NULL DEFAULT '[]'   -- active source ids with sha12
  session          TEXT NOT NULL                 -- F1 at last stamp
  cap              INTEGER NOT NULL
  members          INTEGER NOT NULL
  last_scan_at     TIMESTAMPTZ
  last_scan_ms     INTEGER
  budget           JSONB                          -- {planned_rpm, limit_rpm}
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()

system.radar_membership                           -- one row per EPISODE
  id             BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
  pool_key       TEXT NOT NULL REFERENCES system.radar_pool(pool_key)
  ticker         TEXT NOT NULL
  trade_date     DATE NOT NULL                    -- ET
  first_seen_at  TIMESTAMPTZ NOT NULL
  entered_at     TIMESTAMPTZ                      -- NULL = never admitted
  left_at        TIMESTAMPTZ
  source         TEXT NOT NULL                    -- 'screen:<key>@<sha12>' | 'list:<key>@<sha12>' (best-ranked at first sight)
  sources        JSONB NOT NULL                   -- every source id that listed it while open
  rank_at_entry  INTEGER
  excluded_by    TEXT CHECK (excluded_by IN ('config_cap','not_equity','screen_inactive','manual'))
  session        TEXT NOT NULL                    -- F1 at first sight
  CHECK (entered_at IS NOT NULL OR excluded_by IS NOT NULL)
  CHECK (left_at IS NULL OR left_at >= first_seen_at)
  UNIQUE INDEX (pool_key, ticker) WHERE left_at IS NULL
  INDEX (trade_date, ticker)

"user".aset_sizings  ADD account_mode TEXT CHECK (account_mode IN ('live','sim'))
                     ADD pool_member_id BIGINT REFERENCES system.radar_membership(id)
"user".day_modes     ADD account_mode TEXT CHECK (account_mode IN ('live','sim'))
```

- Episode rules: admitted → `entered_at`, `excluded_by` NULL. Dropped by cap / manual / window → `left_at` + `excluded_by`. Fell off every source → `left_at`, `excluded_by` NULL. Never admitted → `entered_at` NULL + `excluded_by`, closed when it stops being a candidate. Later admission of an excluded candidate closes that episode and opens an admitted one (J1 points at admitted episodes). First active cycle of a new trade date closes every open episode at the prior session end.
- Ownership + grants: `OWNER TO cobalt_system` on both tables; `GRANT SELECT, REFERENCES ON system.radar_membership TO cobalt_user`; `GRANT SELECT ON system.radar_pool TO cobalt_user`.
- Nullable in P1: `pool_member_id` stays nullable forever (manual cards). `account_mode` NOT NULL is a later migration after E1 (the `aset 0004_session → 0005_session_not_null` precedent).
- Rollback SQL: drop `pool_member_id`, both `account_mode` columns, `DROP TABLE system.radar_membership, system.radar_pool`. **Cost, stated:** membership history and account-mode stamps are lost; the L1 `pg_dump` is the belt.
- **Rollback domain fix (F1):** `cobalt db migrate --rollback` REQUIRES `--down-to NNNN` and reverses only registered migrations newer than NNNN, newest first; without it, it refuses and lists targets. Round-trip test: `migrate → --rollback --down-to 0003 → migrate` gives identical digests, and 0003's columns survive the 0004 rollback. **Hardening verdict:** adopted; a whole-list rollback in prod is one keystroke from moving every table to `public`.

### D4 — Pool job `com.cobalt.radar` (F2)

- **Registry:** resident, `supervisor: self`, `timeout_s: 300`, `enabled: false` at merge (flipped in L11 after the first clean scan — `com.cobalt.herdr` precedent, `jobs.yaml:130-136`), `reads:` DERIVED by instrumenting one cycle's `open`/`read_text` (09-09 method), each entry citing file:line.
- **Plist:** `uv run cobalt radar run`; `RunAtLoad true`; `KeepAlive {SuccessfulExit: false}` (a kill-switch exit 0 is not respawned; a crash is); `COBALT_ENV=production`, `COBALT_VAULT_PATH=/Users/cobalt/Vault/Think`; `logs/radar.{log,err}`. `ops/README.md` gains: after `cobalt resume`, `launchctl kickstart gui/$(id -u)/com.cobalt.radar`.
- **Loop:** `job_run` wrapper; `should_keep_running` checked each cycle; one cycle per `radar.scan_interval`.
- **Session gating (asked first, never caught):** F1 session ∉ `active_sessions` (radar.yaml: `premarket, rth, aftermarket`) → `idle`, no Finviz call, pool row stamped. `market_reset` → `paused_market_reset`: ZERO writes to pool, membership, bars or mirror; only the F17 job heartbeat stamps, as the heartbeat fix already does. The decision comes from `session_clock()` before the cycle starts, not from a caught `SessionBlocked` (F10). **A cycle is asked twice:** at start, and again immediately before its single commit (pool + membership in one transaction, then bars, then mirror). A cycle that started at 19:59:50 and would commit at 20:00:05 is dropped whole and logged; no partial write lands in the window.
- **Fetch:** active screens = `enabled ∧ active_from ≤ now_et < active_to ∧ session active` → `GET /export/screener?v=152&f=<f>&o=<sort>&c=0,1,…,150`. Lists with `radar: true` → `GET /export/screener?v=152&t=<chunk>&c=0,…,150` chunked by `list_chunk_size`. Raw responses cached to `data/radar-cache/<trade_date>/<source_key>-<HHMMSS>.csv` (gitignored; retention in radar.yaml). Parsed by header NAME (`required_headers` in radar.yaml; a missing header = source failure). Token via `archiver.collector.resolve_token`; every string through `collector.scrub`.
- **Decision (pure function, no I/O, table-tested):** (1) `exclude` block → `manual`; (2) `not_equity` rule (radar.yaml `{header, values}`; values OBSERVED in a recorded export, never guessed) → `not_equity`; (3) rank per radar.yaml `rank:` — P1 default (E2): screen hits desc → best screen position asc → Relative Volume desc → ticker asc, every list-only name after every screen name; (4) top `radar.pool_cap` admitted, rest `config_cap`; (5) a member whose only sources went inactive (window or `enabled: false`) leaves with `screen_inactive`, unless an active list still carries it; (6) a degraded source's members are held and not re-ranked; it adds no new names. Held members count against the cap FIRST: admissions fill only `pool_cap − held`, and a held member is never evicted to admit a new name, so the cap invariant holds while a source is down.
- **Outage:** HTTP error / non-CSV body / header mismatch → that source degraded (named, `since`), pool row degraded, members held; clears on the next good fetch; F18 RED while degraded. Never an empty pool.
- **Budget:** one token bucket per process for every Finviz call (screener + stock) at `radar.finviz_max_rpm`. `cobalt radar check` (dry-run config check) and `run` startup REFUSE when `cap × 60 / poll_interval + active screens + list chunks per minute > finviz_max_rpm`.

### D5 — Finviz bar poller (same process)

- After each pool step, for admitted members in rank order: `fetch_bars(ticker, Interval.I1, token)`; keep bars with `ts > watermark` (per ticker, seeded from `max(ts)` in `system.bars`) AND `ts + 1 min ≤ now` (closed bars only); `BarStore.upsert_bars` (one path, archiver schema; the 20:30 archiver finalizes the same keys identically).
- **i1 → 2m:** pure `cobalt.archiver.aggregate.aggregate(bars, minutes)`, buckets floored from 00:00 ET, NOT stored. Stored `i2` stays Finviz's own from the archiver, so no key has two writers. Test on the replay day: aggregate(i1) vs archiver i2 → agreement % in the report; any systematic mismatch (bucket alignment, volume) → ESCALATE, never tuned away.
- Cadence `radar.poll_interval` (60 s) → ≥2 polls per 2m bar.

### D8 — `cobalt db query` (R3)

- `cobalt db query --side user|system [--prod] [--format json|table] [--limit 1000] "<sql>"`. Connection = `db.connect(dbname, side=…)` (factory, `cobalt_app`, SET ROLE). `--prod` = `allow_prod=True` (RULING 7 tooling seam); otherwise `env.resolve_db_name()`. Lives in `src/cobalt/db_query.py`, registered under the existing `db` group (`db_migrations/cli.py:196`). No new `psycopg.connect`.
- **Code guard (before the server):** a tokenizer aware of quotes, dollar-quotes and comments. Exactly one statement; first keyword `SELECT` or `WITH`. Refused anywhere as a bare word: INSERT UPDATE DELETE MERGE TRUNCATE CREATE ALTER DROP GRANT REVOKE COPY CALL DO SET RESET LOCK VACUUM ANALYZE REFRESH COMMENT LISTEN NOTIFY PREPARE EXECUTE DEALLOCATE DISCARD INTO, and `FOR UPDATE|SHARE|NO KEY UPDATE|KEY SHARE`. Functions `set_config pg_sleep pg_terminate_backend pg_cancel_backend pg_advisory_* lo_* dblink* pg_read_file pg_read_binary_file pg_ls_dir nextval setval` are refused. Refusal = exit 2 with one loud line naming the token.
- **Belt:** `BEGIN READ ONLY`; `SET LOCAL statement_timeout` from tunable `db.query.timeout_s`; query wrapped `SELECT * FROM (<sql>) AS q LIMIT n` (a data-modifying CTE cannot sit in a subquery); always ROLLBACK; `current_user` asserted equal to the side role afterwards. Output passes through F19 redaction before print.
- Tests: every refused class; keyword inside a string literal passes; multi-statement; data-modifying CTE; `set_config('role', …)` switch; user side reads `system.x` qualified; `cobalt_brain` without `--prod` refuses.
