### The change (`src/cobalt/db_migrations/cli.py` only)
- `DEFAULT_LOCK_TIMEOUT_S = 30`, a module constant with its reasoning beside it.
- `--lock-timeout-s N` (`type=int`, default the constant) on the `migrate` parser.
- Refused **before any connection is opened**, beside the `--proof-only`/`--rollback` refusal: a bool, a non-int, or `< 1` → `MigrationError` — *"0 means wait forever — that is the defect this flag closes."*
- `conn.execute(f"SET LOCAL lock_timeout = '{lock_timeout_s}s'")` in the READ-WRITE branch, between `before = _probe_all(conn)` and `_apply(conn, paths)` — so it covers forward **and** rollback, which share that branch.
- `psycopg.errors.LockNotAvailable` wrapped exactly as `SerializationFailure` already was (`rollback()` → `MigrationError`): says **NOTHING WAS APPLIED**, names the timeout that fired, hands over the `pg_locks` query that finds the holder, and states that raising the flag only makes a stuck deploy wait longer.
- `--proof-only` untouched — a test asserts it sends no `lock_timeout` at all.
- `args.lock_timeout_s` is read with `getattr(..., DEFAULT_LOCK_TIMEOUT_S)`: `tests/cobalt/test_radar_migration.py` builds this Namespace by hand and is **outside this item's bound**, so requiring the attribute would have broken a file the prompt does not name. The parser always sets it; there is one number, named once.

**`DIGEST_EXCLUDED_COLUMNS` NOT touched.** The new constant was deliberately moved
down past `TABLE_DIGEST_EXCLUDED_COLUMNS` so it shares no diff context with the tuple
P4 edits — `git diff` confirms two non-adjacent hunks, keeping the rebase trivial for
whichever branch lands second.

### THE SNAPSHOT — what was decided and why
The requirement is that the BEFORE probe and the migration see **ONE** REPEATABLE READ
snapshot. A snapshot is taken once per such transaction, so a statement issued after
the probe cannot move it. **I could not cite the Postgres manual's wording from this
run** — it is offline by design and no fetch tool is in the allowlist — so I took the
step's own named safe default: *"if you cannot cite it, the `SET LOCAL` goes AFTER
`_probe_all`'s BEFORE pass and before `_apply`, where it cannot matter."* The docstring
says exactly that, including that it is unsettled rather than settled.

**The consequence, named not hidden:** the BEFORE probe is not itself under the ceiling.
It takes ACCESS SHARE, which only an ACCESS EXCLUSIVE holder (another DDL — never a
resident's INSERT/UPDATE) can block. → `## ESCALATE` 2.
