## 6. The comparison and withholding in `append` mode (V2-4 as amended by v3; nobody objected to withholding itself)
One read of the stored rows of the candidate range per target, inside the target's transaction. Per key: in both and EQUAL after normalisation → nothing; only in the download → offered with DO NOTHING; only in storage → `stored_only`, flagged, NOTHING deleted; in both with ANY OHLCV difference → the target's outcome is `restated`: NO insert for that target tonight, stored rows untouched, progress unchanged, a `restated` incident, the target counts FAILED. Never an automatic repair, by constant factor or otherwise. Remedy = `cobalt archiver restate <ticker> [<interval>]`: PREVIEW first (affected range, the differences, what the vendor window covers, what stored history lies outside it and stays unresolved); execution only with `--apply`, inside a quiet window (§8), audit trail on the incident row.


## 8. V3-9 — OPTION A, ruled by the owner (R8): repairs only in a QUIET WINDOW; the live poller is not touched
